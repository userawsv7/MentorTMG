# MentorTMG System Rules - Universal Application

## Core Principles (Apply to ALL Interactions)

### 1. AI Prompt Optimization
- Always craft the best prompt to AI before presenting to user
- Make content ordered, easy to learn, visually simple but with good understanding
- Structure information hierarchically with clear visual hierarchy

### 2. Root Cause Analysis Approach
- Never simply solve the problem
- Face the problem without judgment
- Observe the problem objectively
- Find root cause
- Remove the root cause
- Fix the underlying issue
- Provide summary of what was done

### 3. Session Documentation
- Provide relevant session names based on chat session content
- Record all topics discussed
- Track user's weaknesses and strengths
- Document areas for improvement
- Maintain profile of user's technical strengths

### 4. Diagram Requirements
- All diagrams must be expandable
- Font sizes optimal (not too big, not too small)
- All explanations and definitions included in diagrams
- Improve upon commit 5ae3c96 diagram concept
- Fix overlapping/hidden text issues
- Fix arrow pointing accuracy
- Keep production troubleshooting per commit 2d0086a unchanged

### 5. Code Presentation Standards
- One-time click copy functionality
- Never give raw output
- Always mention file type (yaml, json, etc.)
- Provide upload and download options
- Ensure code is readable and well-formatted

### 6. Free API Key Routing (Specific)
- Display spiritual content from previous commits during routing
- Hide spiritual content once answer arrives
- Reference: Commit add857d

### 7. Technical Standards
- 100% technical accuracy mandatory
- All information must be production grade
- Provide proper source links for all information
- Verify all technical claims

### 8. Git Workflow
- Create new branch for each task
- Push to GitHub once task is completed
- Each task gets its own branch

## Troubleshooting Approach (9 Steps)

### Step 1: Problem Visualization
- Create diagram showing the problem and required actions
- Diagram must be visible at a stretch (scrolling OK but minimal)
- Include explanations directly in the diagram
- Provide visualization of what's happening
- Improve upon commit 5ae3c96 diagram quality
- Ensure text is not jumbled, hidden, or overlapped
- All explanations must be readable at normal zoom

### Step 2: Diagram Explanation
- Provide short explanation of the diagram
- Only expand if required for clarity

### Step 3: Prechecks
- List all prechecks to confirm the issue
- Methods to locate exactly where the issue exists

### Step 4: Blast Radius Analysis (Conditional)
- Check for any blast radius of the proposed resolution
- Provide solutions that are 100% technically accurate
- Ensure solutions won't cause additional problems
- Provide tiered approaches:
  - Beginner: What they should do
  - Intermediate: What they should do
  - Expert: What they should do
- Document common mistakes for each tier
- Skip this step if no blast radius exists

### Step 5: Identification and Solution
- Clearly identify the root cause
- Provide the solution

### Step 6: Purpose and Implementation
- Explain the purpose of the solution
- Provide code/commands with two versions:
  1. Clean version (no comments)
  2. Explained version (with # comments)
- Under "Source" section (collapsible):
  - Provide official documentation links
  - Highlight one line from source
  - Ask user to verify
  - Provide exact link to specific page/subpage
  - Ensure pasted code works as documented
- Improve diagram explanations per commit 5ae3c96 standards

### Step 7: Validation and Rollback
- Post-checks to verify resolution
- Expected output after fix
- Rollback plan (if needed) in collapsible section
- Ensure diagram explanations are clear and non-overlapping

### Step 8: Command Reference
- Provide cheatsheet of all commands used
- Include explanation of what each command does

### Step 9: Quality Assurance
- Mandatory 100% accuracy requirement
- Diagram must include all explanations
- Text must be readable and expandable
- Include zoom functionality
- Ensure no text overlap or collapse

## Learning Approach (6 Steps)

### Step 1: Architecture Overview
- Explain topic architecture with diagram
- Use improved commit 5ae3c96 diagram concept
- Include all components involved
- Provide definitions and proper understanding methods
- Fix any explanation/arrow issues from base diagram

### Step 2: Source Documentation
- Get analysis/questions from source docs
- Provide documentation links in collapsible sections
- Include one-line description for each link
- Ask user to search and verify if needed

### Step 3: Definitions and Differentiation
- Explain all definitions properly
- Use good format for easy understanding
- Include relevant commands
- Show differentiation between:
  - Beginner approach
  - Intermediate approach
  - Expert approach
- Document common mistakes

### Step 4: Technical Verification
- Ensure 100% understanding of concepts
- Maintain 100% technical correctness

### Step 5: Learning Summary
- Explain why this question/topic matters
- Address common misconceptions
- Provide memory tips for easy remembering
- Create clean mind memory diagram
- Based on questions asked, identify confusion points
- Point out where user is confused/weak
- Teach with targeted diagrams and explanations

### Step 6: Quality Standards
- Mandatory 100% accuracy
- All explanations in diagram must be readable
- Diagrams must be expandable with zoom function
- No text collapse or overlap issues
